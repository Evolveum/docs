SCIM 2.0 update operations change the state of a resource.
For a well-behaved SCIM 2.0 server, update works out of the box — no operation script is required.

This document is part of the SCIM 2.0 connector tutorial. See xref:/connectors/scimrest-framework/[] for other topics.

The built-in SCIM update uses the *SCIM `PATCH`* operation (RFC 7644 section 3.5.2) by default: the changed attributes are sent as partial-update operations, and the original resource state is *not* read first.
Use the `scim { put { ... } }` block to opt into a *full `PUT`* (full replacement) instead.

== Built-in update (SCIM PATCH)

The framework translates each ConnId attribute delta into one or more SCIM `PATCH` operations and sends them to `{resource endpoint}/{id}`:

. A *replace* delta becomes a `replace` operation (an empty replace clears the attribute — a `remove` without a value)
. An *add* delta becomes an `add` operation
. A *remove* delta becomes a `remove` operation (carrying the value(s) to remove, or clearing the attribute when none are given)
. The operations are grouped into one or more `PATCH` requests (see `maxPerRequest` below)
. Fails with `ConnectorException` ("Failed to update SCIM resource") on transport or SCIM errors

Because only the changed attributes are sent, no original-state read is needed for the default PATCH strategy.

== Full replacement (SCIM PUT)

To have the framework issue a *full `PUT`* instead — reading the original state and replacing the whole resource — declare the `put` block:

[source,groovy]
----
objectClass("User") {
    update {
        scim {
            put {
                // restrict the full PUT to a supported subset of attributes (optional)
                supportedAttributes "externalId", "displayName", "nickName"
            }
        }
    }
}
----

With the `put` strategy the framework:

. Reads the original state of the object
. Applies each ConnId attribute delta on top of the original values
. Serializes the resulting attributes that the SCIM resource supports into the request body
. Issues a `PUT` to `{resource endpoint}/{id}` with the replacement

NOTE: The `put` and `patch` strategies are mutually exclusive — declaring a `put` block selects full replacement; otherwise the default `PATCH` strategy applies.

== Restricting to a supported subset of attributes

By default all `updateable` attributes from the schema are supported. When a server accepts only part of them, `supportedAttributes` narrows the set the operation handles (for both `put` and `patch`):

[source,groovy]
----
objectClass("User") {
    update {
        scim {
            // the server accepts only these attributes
            patch {
                supportedAttributes "externalId", "displayName", "nickName"
            }
        }
    }
}
----

== Per-attribute limitations (PATCH)

`supportedAttribute(name) { limitations { ... } }` attaches per-attribute limits to the `PATCH` strategy:

[source,groovy]
----
objectClass("User") {
    update {
        scim {
            patch {
                supportedAttributes "externalId", "displayName", "nickName"

                // only ADD and REPLACE are allowed, at most one value per request
                supportedAttribute("userName") {
                    limitations {
                        operations ADD, REPLACE
                        maxPerRequest 1
                    }
                }
            }
        }
    }
}
----

Limitations:

[cols="1,3", options="header"]
|===
|Key |Description

|`operations ADD, REPLACE, REMOVE`
|The SCIM PATCH operations the attribute supports; a delta requiring an unsupported operation fails with a `ConnectorException`

|`maxPerRequest N`
|The maximum number of values of the attribute the server accepts in a single request; when exceeded, the framework splits the update into multiple `PATCH` requests (an over-limit `replace` is sent as a clear followed by chunked `add` operations)

|`value(...)`
|Pins a fixed value for the attribute; the attribute is always sent as a `replace` with this value, ignoring the delta
|===

SCIM PATCH operations: `ADD` (add value(s) to a multi-valued attribute), `REPLACE` (replace value(s)), `REMOVE` (remove value(s) from a multi-valued attribute).

== Disabling update

Use the generic operation enablement (see xref:../rest/update/[] for the REST-side DSL) when a resource type does not support updates at all.
